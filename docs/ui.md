# UI приложения

Интерфейс сцены описывается файлом `ui.html` в папке сцены — подмножеством HTML со встроенным CSS.
Из файла строится дерево узлов `UI_Manager`, раскладку дерева считает Yoga, а каждый рисуемый узел
становится обычной ECS-энтитью, которую рисует UI-проход. **Источник истины — файл**: дерево
строится из него при загрузке сцены, энтити — из дерева.

```
ui.html ──ParseUIMarkup──▶ документ ──UI_Manager::Load──▶ узлы + Yoga ──Emit──▶ энтити
```

Редактор, команды и ввод описаны в [`editor.md`](editor.md).

## Файл

```html
<ui>
  <style>
    *      { quad: ui_quad; }
    ui     { justify-content: flex-end; align-items: center; }
    text   { font-family: default; material: ui_mat; }
    .panel { material: ui_mat; padding: 8px; gap: 8px; }
  </style>
  <box id="hud" class="panel" style="margin: 160px">
    <text>HP: 100<br/>MP: 40</text>
    <box style="material: button_mat; width: 256px; height: 74px"/>
  </box>
</ui>
```

Синтаксис — строгое подмножество HTML: каждый тег закрыт парой или `/>`, значения атрибутов в
кавычках, имена различают регистр. Без закрытия, как в HTML, пишется только `<br>`. Сущности `&lt;
&gt; &amp; &quot; &apos;` и числовые `&#…;` раскрываются, `&` без известной сущности остаётся
буквой, `<` в тексте пишется как `&lt;`. Комментарии `<!-- -->` и `<!DOCTYPE>` пропускаются.
Расширение `.html` даёт подсветку в любом редакторе: файл — как HTML, `<style>` и `style` — как CSS.

| тег | где стоит | что делает |
|---|---|---|
| `<ui>` | корень файла | холст экрана: корень дерева, сам не рисуется |
| `<box>` | в `<ui>` и `<box>` | бокс раскладки; рисуется, если у него есть `material` |
| `<text>` | в `<ui>` и `<box>` | текстовый лист; внутри только текст и `<br/>` |
| `<br/>` | в `<text>` | перенос строки |
| `<style>` | где угодно | CSS-правила файла; узлом не становится |
| `<var>` | в `<ui>` | пропускается: переменные загрузчик пока не исполняет, `{{…}}` в тексте выводится как есть |

| атрибут | у тегов | смысл |
|---|---|---|
| `id` | `<ui>`, `<box>`, `<text>` | имя элемента, уникальное в файле, для селектора `#id` |
| `class` | `<ui>`, `<box>`, `<text>` | имена классов через пробел для селекторов `.class` |
| `style` | `<ui>`, `<box>`, `<text>` | CSS-объявления самого элемента |

Узел в иерархии редактора подписан как в devtools браузера: тег, `#id` и классы — `box#panel.panel`.

### Стили

Правила лежат в `<style>`; блоков может быть несколько. Селекторы — `*`, тег, `.class`, `#id` и их
списки через запятую. Стиль элемента — подстановка: объявления подходящих правил и атрибута `style`
применяются по ступеням, и каждое следующее перекрывает предыдущее.

| ступень | источник |
|---|---|
| 1 | `*` |
| 2 | тег |
| 3 | `.class` |
| 4 | `#id` |
| 5 | `style` |

Внутри ступени порядок задаёт место правила в файле, как в CSS. Правило со списком селекторов встаёт
на ступень самого специфичного из подошедших. Свойства родителя детям не наследуются: общее значение
задаётся правилом `*` или правилом тега.

| свойство | значения |
|---|---|
| `flex-direction` | `row`, `column` |
| `justify-content` | `flex-start` (`start`), `center`, `flex-end` (`end`), `space-between` |
| `align-items` | `flex-start` (`start`), `center`, `flex-end` (`end`), `stretch` |
| `width`, `height` | длина, `N%`, `auto` |
| `flex-grow` | число от нуля |
| `padding`, `margin` | от одной до четырёх длин, как CSS-сокращение; `margin` бывает отрицательным |
| `padding-top`, `-right`, `-bottom`, `-left` и то же у `margin` | одна длина |
| `gap` | длина |
| `material`, `quad` | имя ресурса; `material: none` убирает материал |
| `font-family` | имя шрифта, можно в кавычках |

Длина — `Npx`, ноль можно без единиц. Незаданное берётся из умолчаний Yoga: колонка, дети растянуты
поперёк. Свойство, которое элементу не к чему применить, пропускается: `font-family` у бокса,
`padding` у текста, ресурсы у `<ui>` — их приносят общие правила вроде `*`. Значение проверяется
всегда.

Текст элемента собирается по правилам HTML: серия пробелов и переводов строки становится одним
пробелом, пробелы по краям и у переноса срезаются, перенос задаёт `<br/>`. Отступы исходника на
экран не попадают.

## Перевод: файл в дерево

`Engine::LoadScene` сносит прежнее дерево и, если в папке сцены есть `ui.html`, строит новое через
`UI_Manager::Load` — до генераторов сцены, так что генератор видит готовые узлы. `SaveScene` файл не
пишет: это исходник, а энтити узлов в `scene.sheaf` не сохраняются.

Разбор (`ParseUIMarkup` в `UI_Markup`) превращает текст в документ: дерево элементов и список
правил. Каждый элемент, атрибут, правило и объявление помнит строку файла, а значения — ещё и место
в файле: смещение и длину. Синтаксическая ошибка останавливает разбор на первой же.

Загрузка идёт в два прохода. Первый переводит весь документ в записи узлов и проверяет смысл:
незнакомые тег, атрибут, свойство или значение, `<text>` без шрифта, материала или квада. Второй
вызывает `Root`, `Box` и `Text` — только если ошибок нет. Ошибки собираются все и уходят в лог с
`файл:строка`, а прежнее дерево остаётся.

Файл правят при запущенной сцене: кнопка Load в разделе UI иерархии редактора шлёт команду, и
sim-поток перечитывает `ui.html` загруженной сцены (`Engine::LoadUI`) под тем же `scene_swap_mutex`,
что и загрузка сцены, — загрузка перестраивает вектор узлов, по которому панели ходят с рендер-потока.
Узлы при этом нумеруются заново, поэтому выделенный UI-узел сбрасывается. С опечаткой в сохранённом
файле на экране остаётся прежнее дерево, а ошибки уходят в лог.

## Исполнение: Yoga и энтити

`UI_Manager` держит дерево узлов. Узел — это Yoga-узел со своим стилем (`UIStyle`) и, если узлу есть
чем рисоваться, ECS-энтить: quad с материалом узла. Раскладку Yoga считает **в пикселях окна**:
размеры элементов заданы относительно экрана, а внутреннее разрешение бывает и выше, и ниже окна.

`Emit` идёт на sim-потоке в начале подготовки кадра ([`render-pipeline/frame.md`](render-pipeline/frame.md)).
На структурном изменении дерева — узлы добавили или убрали, узел без материала получил его или
потерял — энтити пересоздаются. Остальные правки — смещение, стиль, матрица `local`, материал, текст,
размер окна — `Emit` переносит в `Positions`, `UITextComponent` и `Renderable` существующих энтити на
месте. Пересоздание каждый кадр было бы структурной мутацией ECS во время обхода панелями редактора
с другого потока.

Размер и масштаб узла — разные правки. Размер входит в стиль: он меняет раскладку, текст переносится
заново, авто-родители растут. Масштаб живёт в `local` и применяется после раскладки: растягивает quad
самого узла, детей не трогает. Стиль, материал и `local` живого узла редактор правит командами.

Текстовый узел — лист Yoga с measure-функцией: раскладка спрашивает текст о размере при доступной
ширине, и текст отвечает, перенеся строки по пробелам. Заданная сверху ширина переносит текст,
авто-размер толкает узел и его авто-родителей; слово шире доступного вылезает, как в CSS. После
раскладки `Emit` переносит строки заново по итоговой ширине узла и кладёт их в `UITextComponent`
([`render-pipeline/instance-data.md`](render-pipeline/instance-data.md)). Строку живого узла меняет
`SetText`: узел раскладывает её в глифы своего шрифта, Yoga перемеряет, дальше всё идёт как при
правке стиля. Та же строка ничего не меняет, поэтому `SetText` можно звать каждый тик.

Шейдер рисует текст размером шрифта от левого верхнего угла узла. Перенос в потоке глифов — код
`UI_LINE_BREAK_CODE`, шейдер получает его дефайном. Ячейка глифа занимает всю высоту строки и выровнена
по базовой линии, поэтому строки встают друг под друга без отдельных метрик.

## Инварианты и грабли

- **При ошибке в файле дерево остаётся прежним.** Загрузка проверяет документ целиком до первого
  узла.
- **`flex-direction` по умолчанию — `column`**, как в Yoga. В браузере по умолчанию `row`, и
  разметка, перенесённая оттуда без явного направления, ляжет иначе.
- **Стили не наследуются.** Шрифт и другие общие свойства задаются правилом `*` или правилом тега.
- **Порядок имён в `class` на результат не влияет.** При равной специфичности побеждает правило,
  которое ниже в файле.
- **UI-энтити пересоздаются только на структурном изменении дерева.**
- **Текстовый узел — лист.** У узла с measure-функцией Yoga запрещает детей: вставка ребёнка в текст
  падает на её assert.
- **Отступ текста задаёт родительский бокс.** Шейдер рисует текст от угла рамки узла, поэтому
  `padding` текстового узла всегда 0.
- **Текст за рамкой своего узла не рисуется** — его рисует quad узла. За родительский бокс он
  вылезти может: у текстового узла своя рамка, и Yoga не сжимает её под родителя.
- **Переносы `Emit` делает с запасом в пиксель.** Yoga округляет раскладку, и итоговая ширина
  расходится с замеренной на долю пикселя; без запаса строка, влезшая при замере, перенеслась бы, и
  текст стал бы выше своего узла.
