# UI приложения

Интерфейс сцены описывается файлом `ui.html` в папке сцены — подмножеством HTML со встроенным CSS.
Из файла строится дерево узлов `UI_Manager`, раскладку дерева считает Yoga, а каждый рисуемый узел
становится обычной ECS-энтитью, которую рисует UI-проход. **Источник истины — файл**: дерево
строится из него при загрузке сцены, энтити — из дерева. Данные игры попадают в файл через
переменные: игра записывает значение, и зависящие от него узлы обновляются на месте.

```
ui.html ──ParseUIMarkup──▶ документ ──UI_Manager::Load──▶ узлы + Yoga ──Emit──▶ энтити
                                                              ▲
                          SetVar ──▶ пул связей ──ApplyDirtyBindings
```

Редактор, команды и ввод описаны в [`editor.md`](editor.md).

## Файл

```html
<ui>
  <var name="hp" default="100"/>
  <style>
    *      { quad: ui_quad; }
    ui     { justify-content: flex-end; align-items: center; }
    text   { font-family: default; material: ui_mat; }
    .panel { material: ui_mat; padding: 8px; gap: 8px; }
  </style>
  <box id="hud" class="panel" style="margin: 160px">
    <text>HP: {{hp}}<br/>MP: 40</text>
    <box style="material: button_mat; width: 256px; height: 74px"/>
  </box>
</ui>
```

Синтаксис — строгое подмножество HTML: каждый тег закрыт парой или `/>`, значения атрибутов в
кавычках, имена различают регистр. Без закрытия, как в HTML, пишется только `<br>`. Сущности `&lt;
&gt; &amp; &quot; &apos;` и числовые `&#…;` раскрываются, `&` без известной сущности остаётся
буквой, `<` в тексте пишется как `&lt;`. Комментарии `<!-- -->` и `<!DOCTYPE>` пропускаются.
Расширение `.html` даёт подсветку в любом редакторе: файл — как HTML, `<style>` и `style` — как CSS.

| тег | где стоит | что делает |
|---|---|---|
| `<ui>` | корень файла | холст экрана: корень дерева, сам не рисуется |
| `<box>` | в `<ui>` и `<box>` | бокс раскладки; рисуется, если у него есть `material` |
| `<text>` | в `<ui>` и `<box>` | текстовый лист; внутри только текст и `<br/>` |
| `<input>` | в `<ui>` и `<box>` | текстовый лист с вводом по клику; содержимое ссылается ровно на одну переменную, обязательны `caret-material` и `caret-quad` |
| `<scrollbar>` | в `<ui>` и `<box>` | полоса прокрутки бокса из `for`; пустой лист, обязательны `thumb-material` и `thumb-quad` |
| `<br/>` | в `<text>` и `<input>` | перенос строки |
| `<style>` | где угодно | CSS-правила файла; узлом не становится |
| `<var>` | в `<ui>` | объявляет переменную для `{{…}}`; узлом не становится |
| `<for>` | в `<ui>`, `<box>` и `<for>` | повторяет содержимое по числу экземпляров; узлом не становится |

| атрибут | у тегов | смысл |
|---|---|---|
| `id` | `<ui>`, `<box>`, `<text>`, `<input>`, `<scrollbar>` | имя элемента, уникальное в файле, для селектора `#id` и поиска узла из кода (`FindNode`); у экземпляров цикла общее |
| `class` | `<ui>`, `<box>`, `<text>`, `<input>`, `<scrollbar>` | имена классов через пробел для селекторов `.class` |
| `style` | `<ui>`, `<box>`, `<text>`, `<input>`, `<scrollbar>` | CSS-объявления самого элемента |
| `for` | `<scrollbar>` | `id` бокса, который полоса прокручивает; обязателен |
| `axis` | `<scrollbar>` | ось полосы: `y` — умолчание, `x` |
| `name` | `<var>` | имя переменной: латинские буквы, цифры и `_`, первой не цифра |
| `default` | `<var>` | значение, пока игра переменную не записала; без атрибута — пустая строка |

Узел в иерархии редактора подписан как в devtools браузера: тег, `#id` и классы — `box#panel.panel`.
У экземпляра цикла к подписи дописан его ключ: `text.cell[1][2]`.

### Стили

Правила лежат в `<style>`; блоков может быть несколько. Селекторы — `*`, тег, `.class`, `#id` и их
списки через запятую. Стиль элемента — подстановка: объявления подходящих правил и атрибута `style`
применяются по ступеням, и каждое следующее перекрывает предыдущее.

| ступень | источник |
|---|---|
| 1 | `*` |
| 2 | тег |
| 3 | `.class` |
| 4 | `#id` |
| 5 | `style` |

Внутри ступени порядок задаёт место правила в файле, как в CSS. Правило со списком селекторов встаёт
на ступень самого специфичного из подошедших. Свойства родителя детям не наследуются: общее значение
задаётся правилом `*` или правилом тега.

| свойство | значения |
|---|---|
| `display` | `flex`, `none` |
| `flex-direction` | `row`, `column` |
| `justify-content` | `flex-start` (`start`), `center`, `flex-end` (`end`), `space-between` |
| `align-items` | `flex-start` (`start`), `center`, `flex-end` (`end`), `stretch` |
| `width`, `height` | длина, `N%`, `auto` |
| `min-width`, `min-height` | длина, `N%`, `auto` — без нижней границы, умолчание |
| `max-width`, `max-height` | длина, `N%`, `none` — без верхней границы, умолчание |
| `flex-grow` | число от нуля |
| `flex-shrink` | число от нуля; умолчание `0` |
| `padding`, `margin` | от одной до четырёх длин, как CSS-сокращение; `margin` бывает отрицательным |
| `padding-top`, `-right`, `-bottom`, `-left` и то же у `margin` | одна длина |
| `gap` | длина |
| `overflow` | одно или два значения `overflow-x`: первое для x, второе для y; одно — для обеих осей |
| `overflow-x`, `overflow-y` | `visible` — умолчание, `hidden`, `scroll`, `auto` |
| `material`, `quad` | имя ресурса; `material: none` убирает материал |
| `font-family` | имя шрифта, можно в кавычках |
| `caret-material`, `caret-quad` | имя ресурса каретки `<input>` |
| `caret-width` | ширина каретки `<input>`: длина или `N%` от высоты строки; умолчание `2px` |
| `caret-gap` | сдвиг каретки `<input>` влево от буквы: длина или `N%` от высоты строки; умолчание `0` |
| `thumb-material`, `thumb-quad` | имя ресурса бегунка `<scrollbar>` |
| `thumb-hover-material`, `thumb-active-material` | имя материала бегунка при наведении и при захвате |

Длина — `Npx`, ноль можно без единиц; `N%` у размеров и границ берётся от размера родителя. Границы
`min-*` и `max-*` ограничивают итоговый размер, откуда бы он ни взялся: из `width`, растяжения,
сжатия или содержимого. Нижняя сильнее верхней, как в CSS, а текст с `max-width` переносится по ней.
Незаданное берётся из умолчаний Yoga: колонка, дети растянуты поперёк и вдоль не сжимаются.
Свойство, которое элементу не к чему применить, пропускается: `font-family` у бокса, `padding` и
`overflow` у текста, ресурсы у `<ui>` — их приносят общие правила вроде `*`. Значение проверяется
всегда.

Текст элемента собирается по правилам HTML: серия пробелов и переводов строки становится одним
пробелом, пробелы по краям и у переноса срезаются, перенос задаёт `<br/>`. Отступы исходника на
экран не попадают.

## Перевод: файл в дерево

`Engine::LoadScene` сносит прежнее дерево и, если в папке сцены есть `ui.html`, строит новое через
`UI_Manager::Load` — до генераторов сцены, так что генератор видит готовые узлы. `SaveScene` файл не
пишет: это исходник, а энтити узлов в `scene.sheaf` не сохраняются.

Разбор (`ParseUIMarkup` в `UI_Markup`) превращает текст в документ: дерево элементов и список
правил. Каждый элемент, атрибут, правило и объявление помнит строку файла, а значения — ещё и место
в файле: смещение и длину. Синтаксическая ошибка останавливает разбор на первой же.

Загрузка идёт в два прохода. Первый переводит весь документ в элементы (`UIElement`) и проверяет
смысл: незнакомые тег, атрибут, свойство или значение, `<text>` и `<input>` без шрифта, материала или
квада, `<input>` не с одной переменной, необъявленная переменная, заголовок `<for>` не по форме,
`<scrollbar>` без бегунка или со связью, которую нельзя провести (раздел «Полоса прокрутки»). Переменные `<var>` загрузчик читает раньше
элементов: в `{{…}}` при проверке уже подставлены их значения. Второй проход строит по элементам
узлы через `Root`, `Box`, `Text`, `Input` и `Scrollbar`, разворачивает циклы и заводит связи переменных — только если
ошибок нет. Ошибки собираются все и уходят в лог с `файл:строка`, а прежнее дерево остаётся.
Элементы остаются у менеджера: по ним строятся новые экземпляры, когда цикл растёт, и пересобираются
текст и стиль узла, когда меняется переменная.

Вид элемента и вид узла заданы тегом и потом не меняются, поэтому каждый хранит только свои поля:

| тег | элемент | узел | что лежит только у него |
|---|---|---|---|
| `<ui>` | `UIRootElement` | бокс | дети |
| `<box>` | `UIBoxElement` | `UIBoxData` | дети |
| `<text>` | `UITextElement` | `UITextData` | шаблон текста; у узла — глифы, перенос и места символов |
| `<input>` | `UIInputElement` | `UIInputData` | то же, что у текста, и каретка: её материал, модель и энтити |
| `<scrollbar>` | `UIScrollbarElement` | `UIScrollbarData` | ось и связь со списком: у элемента — `id` из `for`, у узла — номер узла; у узла ещё бегунок: материалы трёх состояний, модель, текущее состояние и энтити |
| `<for>` | `UILoopElement` | — | шаблон числа экземпляров и дети |

Элементы, из которых строятся узлы, делят общую часть `UIElementStyle`: `id` и классы, объявления
каскада, связанные свойства, правки редактора и место атрибута `style` в файле, куда Save их впишет.

Файл правят при запущенной сцене: кнопка Load в разделе UI иерархии редактора шлёт команду, и
sim-поток перечитывает `ui.html` загруженной сцены (`Engine::LoadUI`) под тем же `scene_swap_mutex`,
что и загрузка сцены, — загрузка перестраивает вектор узлов, по которому панели ходят с рендер-потока.
Узлы при этом нумеруются заново, поэтому выделенный UI-узел сбрасывается. С опечаткой в сохранённом
файле на экране остаётся прежнее дерево, а ошибки уходят в лог.

## Переменные: данные игры в файле

Переменная — именованное значение, которое пишет игра, а читает файл. Файл объявляет её в `<ui>`
тегом `<var name="hp" default="100"/>` и подставляет как `{{hp}}`: в текст `<text>` и в значения
свойств — в атрибуте `style` и в правилах `<style>`. Пробелы внутри скобок допустимы: `{{ hp }}`.
Подстановка текстовая, без вычислений: при `hp = 75` объявление `width: {{hp}}%` читается как
`width: 75%`. Внутри скобок стоит имя переменной или индекса цикла, а у переменной — ещё и номер
элемента: `{{icon[i]}}` (раздел «Циклы»).

Значение задаёт игра — в том месте кода, где меняются сами данные:

```cpp
const UIVarId hp = ctx->GetUIManager()->InternVar("hp");   // один раз, до загрузки файла или после
ctx->GetUIManager()->SetVar(hp, player_hp);                 // там, где меняется хп
```

Ссылки на источник данных у UI нет: значение хранит `UI_Manager`, а у игры есть только `UIVarId` —
номер ячейки в реестре переменных, как `FontId` у шрифта. `SetVar` принимает строку или число; число
записывается кратчайшей записью, `0.1f` даёт `0.1`. Прежнее значение ничего не меняет, поэтому писать
можно и каждый тик. `SetVar` зовут с sim-потока, где идут код игры и `Emit`.

**Переменные принадлежат менеджеру, а не дереву.** Перезагрузка файла и загрузка сцены пересобирают
дерево, а переменные, их id и записанные игрой элементы остаются, и новое дерево сразу показывает
значения игры. `default` из файла действует, пока игра переменную или элемент не записала.

Каждое место с `{{…}}` при загрузке становится связью узла с переменными. У текста связь — шаблон
строки. У стиля — весь список объявлений узла: связанное объявление может перекрываться следующими,
в том числе частично (`padding` и `padding-left`), поэтому стиль собирается заново целиком. Каждая
переменная помнит свои связи, и `SetVar` с новым значением ставит их в пул — список помеченных
связей, каждую по одному разу. Пул разбирает `ApplyDirtyBindings` раз в кадр перед `Emit`, так что
строка из двух переменных, изменённых в одном тике, собирается один раз.

| что связано | чем применяется | что дальше |
|---|---|---|
| текст `<text>` | `SetText` | глифы, замер, перераскладка |
| свойства раскладки | `SetNodeStyle` | перераскладка |
| `material` | `SetNodeMaterial` | смена материала на месте; бокс, получивший или потерявший материал, — структурное изменение |
| число экземпляров `<for>` | `ResizeLoop` | запас или постройка экземпляров |

`quad`, `font-family`, `id` и `class` читаются один раз при загрузке, и `{{…}}` в них — ошибка.
Подставленное значение проверяется так же, как литерал. При загрузке проверка идёт с текущими
значениями переменных. Неверное значение от `SetVar` уходит в лог с `файл:строка`, и узел собирается
из остальных объявлений.

## Циклы: повтор по индексам

`<for>` повторяет своё содержимое: каждый экземпляр — копия тела цикла со своим номером. Узлом
`<for>` не становится: экземпляры встают в родителя на его место, и раскладка родителя видит их
напрямую.

```html
<var name="slots" default="6"/>
<var name="icon" default="slot_empty"/>
<var name="amount"/>

<box class="hotbar">
  <for i in range(slots)>
    <box class="slot" style="material: {{icon[i]}}">
      <text>{{amount[i]}}</text>
    </box>
  </for>
</box>
```

Заголовок — `ИМЯ in range(ЧИСЛО)`, где число — литерал, переменная или индекс внешнего цикла:
`range(6)`, `range(slots)`, `range(cols[i])`. Индекс виден только в теле своего цикла, `_` — индекс
без имени. В заголовке и внутри `{{…}}` голое имя — переменная или индекс, цифры — число, а строк
нет вовсе: строка — всё, что снаружи.

Индекс экземпляра — целое число, постоянное у экземпляра. `{{i}}` подставляет его текстом, а
`{{icon[i]}}` берёт элемент переменной с этим номером. В квадратных скобках стоят только индексы
циклов и числа, поэтому элемент, на который смотрит экземпляр, известен при постройке, и связь
заводится на нём одном. Переменная хранит элементы по ключу — набору индексов (`UIVarKey`); ключ без
индексов — сама переменная. Элемент, который игра не писала, берёт `default` переменной; с ним же
загрузка проверяет подстановку, а индекс цикла проверяет как 0.

```cpp
ui->SetVar(slots, 8);                    // число экземпляров — обычная переменная
ui->SetVar(icon, { 3 }, "sword_mat");    // элемент 3
ui->SetVar(cell, { row, col }, 12);      // элемент вложенного цикла; индексы — uint32_t
```

`SetVar` элемента ставит в пул только связи экземпляра с этим ключом. Значение, записанное раньше,
чем построен экземпляр, ждёт его: экземпляр строится с текущими значениями.

Число экземпляров — связь цикла с переменной. Когда число падает, лишние экземпляры уходят в
**запас**: их узлы получают флаг `parked`, Yoga убирает их из раскладки, как `display: none`, а `Emit`
снимает их энтити с отрисовки. Флаг запаса отделён от `display`: связь стиля пересобирает стиль из
файла и вернула бы спрятанному экземпляру `display: flex`. Когда число растёт, сначала возвращаются
экземпляры из запаса, и только сверх него строятся новые. Запас растёт до наибольшего числа, которое
видел цикл, и сбрасывается перезагрузкой файла.

Постройка экземпляра — структурное изменение. Его узлы дописываются в конец `nodes`, а порядок файла
среди детей родителя возвращает `RebuildChildren`: родитель хранит детей слотами «узел или цикл»
(`UISlot`), и список детей — развёртка этих слотов по экземплярам. Рост идёт в `ApplyDirtyBindings`
под `scene_swap_mutex`, как загрузка файла: панели редактора ходят по `nodes` с рендер-потока, и
перевыделение вектора под ними было бы чтением освобождённой памяти. Sim-поток ждёт конца кадра
рендера только тогда, когда цикл растёт сверх запаса.

Циклы вкладываются, и ключ элемента внутреннего цикла — индексы всех объемлющих: `{{cell[i][j]}}`.
Узел помнит ключ своего экземпляра (`UINode::instance`), и код находит узел экземпляра по `id` и
ключу: `FindNode("slot", { 3 })`.

## Исполнение: Yoga и энтити

`UI_Manager` держит дерево узлов. Узел — это Yoga-узел со своим стилем (`UIStyle`) и ECS-энтить.
Энтить узла, которому есть чем рисоваться, — quad с материалом узла. У бокса без материала энтить
без `Renderable` и `Positions`: в отрисовку она не попадает и строки в буфере трансформов не
занимает. Раскладку Yoga считает **в пикселях окна**:
размеры элементов заданы относительно экрана, а внутреннее разрешение бывает и выше, и ниже окна.

`Emit` идёт на sim-потоке в начале подготовки кадра ([`render-pipeline/frame.md`](render-pipeline/frame.md)).
На структурном изменении дерева — узлы добавили или убрали, узел без материала получил его или
потерял, бокс получил `overflow` или потерял его — энтити пересоздаются. Остальные правки — смещение,
стиль, матрица `local`, материал, текст, размер окна — `Emit` переносит в `Positions`,
`UITextComponent`, `Renderable` и рамки обрезки существующих энтити на месте. Пересоздание каждый кадр было бы структурной мутацией ECS во время обхода панелями редактора
с другого потока.

Код игры находит узел по `id` из файла (`FindNode`) и проверяет, попадает ли в него точка окна
(`NodeContains`), например курсор. Точка переводится в систему узла обратной матрицей `local`, так
что поворот и масштаб узла в плоскости экрана учтены. Через `GetNodeEntity` код получает энтить узла,
например чтобы переключить ей вариант текстуры.

Узел с `display: none` скрыт вместе с поддеревом. Yoga не отводит ему места, и соседи смыкаются.
Энтити поддерева остаются в ECS, а `Emit` снимает им флаг `Renderable.visible` через `HideEntity`, и
в список отрисовки они не попадают. `NodeContains`
скрытому узлу отвечает «нет», а виден ли узел с учётом предков, говорит `IsNodeShown`. Скрытие —
правка стиля, а не структуры: снова показанный узел рисуют те же энтити с тем же состоянием. Связи
скрытого узла применяются как обычно, и показанный узел сразу выводит текущие значения. Цена
переключения — полный пересчёт населения отрисовки в кадре правки
([`render-pipeline/batches.md`](render-pipeline/batches.md)): он идёт по всем сущностям сцены, а не
только по узлам UI.

Размер и масштаб узла — разные правки. Размер входит в стиль: он меняет раскладку, текст переносится
заново, авто-родители растут. Масштаб живёт в `local` и применяется после раскладки: растягивает quad
самого узла, детей не трогает. Стиль, материал и `local` живого узла редактор правит командами
(раздел «Правки редактора и сохранение»).

Текстовый узел — лист Yoga с measure-функцией: раскладка спрашивает текст о размере при доступной
ширине, и текст отвечает, перенеся строки по пробелам. Заданная сверху ширина переносит текст,
авто-размер толкает узел и его авто-родителей; слово шире доступного вылезает, как в CSS. После
раскладки `Emit` переносит строки заново по итоговой ширине узла и кладёт их в `UITextComponent`
([`render-pipeline/instance-data.md`](render-pipeline/instance-data.md)). Строку живого узла меняет
`SetText`: узел раскладывает её в глифы своего шрифта, Yoga перемеряет, дальше всё идёт как при
правке стиля. Та же строка ничего не меняет, поэтому `SetText` можно звать каждый тик.

Шейдер рисует текст размером шрифта от левого верхнего угла узла. Перенос в потоке глифов — код
`UI_LINE_BREAK_CODE`, шейдер получает его дефайном. Ячейка глифа занимает всю высоту строки и выровнена
по базовой линии, поэтому строки встают друг под друга без отдельных метрик.

## Обрезка: `overflow`

Бокс с `overflow`, отличным от `visible`, обрезает потомков по области, которую им отдаёт: своей
рамке за вычетом `padding`. У каждой оси обрезка своя: `overflow-x` режет слева и справа,
`overflow-y` — сверху и снизу, а вдоль оси с `visible` потомки выходят за область как обычно.
Потомок целиком за областью не рисуется и кликов не ловит, но место в раскладке за ним остаётся.
Частично видимый обрезан по её краю, и клик по срезанной части до него не доходит. Вложенные боксы
с `overflow` режут по пересечению своих областей. `hidden` только режет, а `scroll` и `auto` ещё и
прокручивают (раздел «Прокрутка») и пока ведут себя одинаково. Обрезает только бокс и `<ui>`; у
текста и поля `overflow` пропускается.

Вдоль главной оси бокса (`flex-direction`) `overflow` меняет и раскладку: Yoga меряет детей по их
содержимому, а не по размеру бокса. Без этого текст в горизонтальной полосе сжался бы под её ширину
и перенёсся, а с `overflow-x` у строки он ложится в одну строку и растёт до своего `max-width`. У
колонки раскладка не меняется: высоту по содержимому её дети получают и так.

Рамку обрезки `Emit` считает при обходе дерева, в пикселях окна. Область бокса — его раскладка без
`padding`, который посчитала Yoga, — пересекается с рамкой ближайшего обрезающего предка, а вдоль
оси с `visible` рамка берётся у предка или у окна. Матрица
`local` в рамку не входит: поворот и масштаб из гизмо обрезку не сдвигают. Рамки нумеруются по
порядку обхода и лежат в `UIClipRectComponent` на энтити бокса. Рисующая энтить под обрезающим
боксом получает `UIClipComponent` с номером рамки ближайшего такого предка, каретка — номер рамки
своего поля. Номера и рамки `Emit` переписывает на месте, а появление и снятие обрезки у бокса —
структурное изменение: компонент нельзя добавить существующей энтити.

`UI_ClipDataModule` каждый кадр собирает из этих компонентов разреженный канал — тот же механизм,
что у текста (`sparse_rank.hlsli`):

| буфер | что лежит |
|---|---|
| `UIClipRank` | бит на строку трансформа с `UIClipComponent` и счёт битов до каждого слова |
| `UIClipIndex` | номер рамки на каждый бит |
| `UIClipRect` | рамка в NDC окна: лево, верх, право, низ |

Вершинник `ui.vert` берёт рамку своей строки и пишет в `SV_ClipDistance0` четыре расстояния до её
сторон, а видеокарта отбрасывает часть квада вне рамки ещё до фрагментника. Расстояния считаются до
деления на `w`, поэтому срез ровный и под перспективой `ui_camera`. Квад целиком за рамкой
отбрасывается целиком. Строка без бита получает положительные расстояния и не режется. Клики проверяют то же на CPU: `NodeContains` идёт по предкам узла через его
`parent` и отвечает «нет», если точка вне области обрезающего предка по его обрезающей оси. Область
для рамки и для клика считает одна функция, `UINode::ContentBox`, поэтому видимое и кликабельное
совпадают.

## Прокрутка

Бокс с `overflow: scroll` или `auto` по оси прокручивается по ней колесом мыши. Прокрутка сдвигает
детей внутри области обрезки бокса, а раскладка остаётся прежней: Yoga кладёт детей как без
прокрутки, и `EmitNode` вычитает сдвиг из начала координат детей. Поэтому поворот колеса — не правка
стиля, а перенос `Positions` на месте.

**Состояние прокрутки живёт в менеджере, а не в узле и не на энтити.** Это запись `UIScrollView` в
списке `UI_Manager::scroll_views`: номер бокса, сдвиг и предел по каждой оси. Предел — на сколько
содержимое длиннее видимой области. Край содержимого — наибольший правый и нижний край прямого
ребёнка вместе с его `margin`, видимая область — рамка бокса без правого и нижнего `padding`. Запись
заводит `EmitNode` при первом обходе бокса, а на каждой раскладке пересчитывает предел и зажимает в
него сдвиг, поэтому укоротившийся список сам доезжает до нового конца.

| событие | запись |
|---|---|
| пересоздание энтити | остаётся |
| `display: none` у бокса или предка | остаётся, предел не пересчитывается: Yoga обнуляет раскладку скрытого поддерева, и после показа список стоит там же |
| бокс или предок ушёл в запас цикла | удаляется, вернувшийся экземпляр стоит с начала |
| стиль бокса перестал прокручивать | удаляется |
| загрузка файла | список очищается |

Сдвиг хранится дробным, а к детям применяется округлённым до пикселя. Yoga кладёт узлы на целые
пиксели, а тачпад даёт дробные повороты: текст между пикселями размылся бы, а медленная прокрутка
тачпадом без дробного хранения стояла бы на месте.

Колесо проходит три шага:

| шаг | поток | что происходит |
|---|---|---|
| приём | main | `InputManager` кладёт поворот в очередь ввода UI вместе с точкой курсора; с Shift вертикальный поворот становится горизонтальным, а на macOS это делает сама система |
| отсев | sim, перед тиком приложения | `ProcessUIInput` выбрасывает повороты, пока мышь занята панелью редактора |
| прокрутка | sim, перед тиком приложения | `HandleInput` складывает повороты тика и передаёт сумму в `ScrollByWheel` |

Выбор цели повторяет ImGui (`UpdateMouseWheel`). Цель — узел под курсором или ближайший его предок с
ненулевым пределом по оси поворота. Поэтому вложенный список крутится раньше внешнего, а дойдя до
края, оставляет колесо у себя. Цель удерживается: следующие повороты идут в тот же бокс, пока курсор
не отошёл больше чем на 6 пикселей от точки, где цель выбрана, и пока не вышло время удержания.
Каждый поворот добавляет к нему 0,7 с на полный щелчок, всего не больше 0,7 с. Так прокрутка не
перескакивает на вложенный список, который подъехал под неподвижный курсор.

Поворот сразу по двум осям, как у тачпада, крутит одну из них — ту, по которой скользящее среднее
поворотов за последние 30 тиков больше; при равенстве крутится вертикаль. Щелчок сдвигает на 64
пикселя по вертикали и на 26 по горизонтали — 5 и 2 высоты 13-пиксельного шрифта ImGui, — но не
больше двух третей видимой области. `SetMouseEnabled(false)` выключает и прокрутку.

### Полоса прокрутки

Полоса — отдельный элемент `<scrollbar>`, который показывает, где в списке стоит прокрутка. Список
она находит по `id` из `for`, а место ей задаёт обычная раскладка, как любому боксу. Дети одного
родителя по умолчанию идут колонкой, поэтому вертикальную полосу кладут со списком в ряд, а
горизонтальную ставят следом за списком:

```html
<box style="flex-direction: row">
  <box id="list" style="overflow-y: scroll; height: 200px"> ... </box>
  <scrollbar for="list" style="thumb-material: thumb_mat; thumb-quad: ui_quad"/>
</box>
```

В ряду полоса растягивается на высоту ряда, то есть на высоту списка. Толщина без `width` у
вертикальной полосы и без `height` у горизонтальной — 14 пикселей. Сам список о полосе не знает и
новых свойств не получает: у одного списка может быть несколько полос или ни одной.

Полоса рисуется в два слоя:

| слой | что это | чем задаётся |
|---|---|---|
| дорожка | весь бокс полосы, вместе с `padding` | `material` и `quad` полосы, как у бокса; без материала дорожка не рисуется |
| бегунок | часть дорожки, которая показывает видимую долю списка | `thumb-material` и `thumb-quad`, обязательны; `thumb-hover-material` и `thumb-active-material` по желанию |

Бегунок ходит по боксу полосы без её `padding`. Длина бегунка — доля видимой области в длине
содержимого, умноженная на длину этого бокса, но не меньше 12 пикселей. Положение — доля сдвига в
пределе прокрутки, отложенная на свободной части бокса, как в ImGui (`ScrollbarEx`). Поперёк бегунок
занимает бокс целиком, поэтому `padding` полосы задаёт зазор между краем дорожки и бегунком. Края
бегунка округляются до пикселя. Когда прокручивать нечего, бегунок занимает весь бокс, а полоса
остаётся на месте и место в раскладке за собой держит.

**Бегунок — своя энтить полосы**, как каретка у поля, но без родителя. Его создаёт `EmitNode` вместе
с энтитью полосы и удаляет `Emit` вместе с остальными энтити UI. Матрицу ему пишет `UpdateThumbs`
после обхода всего дерева: матрица полосы, умноженная на долю бегунка в ней, так что поворот и
масштаб `local` полосы на бегунок действуют. Размер бегунка лежит в его матрице, поэтому материал на
`UINineSlice` рисует его с целыми углами, а обычный материал растягивает. По глубине бегунок занимает
шаг сразу за полосой: перед дорожкой и за следующим узлом.

Связь проверяет загрузка, после перевода всего документа: список может стоять в файле после полосы.
Ошибка загрузки — когда:

- элемента с этим `id` нет, или это не `<box>` и не `<ui>`;
- полоса лежит внутри самого списка — она уехала бы вместе с содержимым;
- список повторяется в `<for>`, а полоса стоит снаружи этого цикла, и непонятно, какой экземпляр
  она крутит;
- `overflow` списка по оси полосы не `scroll` и не `auto`.

Полоса в том же теле цикла, что и список, берёт список своего экземпляра: ключ списка — начало ключа
полосы длиной в число циклов вокруг списка. Номер узла списка полоса находит после постройки дерева
и после роста цикла (`ResolveScrollbarTargets`).

Полоса перекрывает клик всем своим боксом, даже без материала дорожки, а колесо над ней прокручивает
её список. Нажатие на полосу кликом не становится: оно захватывает полосу до отпускания кнопки, как
`ScrollbarEx` в ImGui. Страница — длина видимой области списка по оси полосы.

| нажатие | что происходит |
|---|---|
| на бегунок | бегунок идёт за курсором по оси полосы, и точка, за которую его взяли, остаётся под курсором; поперёк курсор может уйти с полосы, а за концами дорожки бегунок стоит у края |
| на дорожку до или после бегунка | список сдвигается на страницу в сторону курсора; пока кнопка зажата, сдвиг повторяется через 0,275 с и дальше каждые 0,05 с, если курсор всё ещё по ту же сторону бегунка |
| с Shift, куда угодно на полосе | центр бегунка встаёт под курсор, дальше — как при нажатии на бегунок |

Захват — запись `UIScrollbarDrag` в менеджере: номер полосы и вид захвата. У бегунка это смещение
курсора от его начала, у страниц — направление и время следующего повтора. Запись заводит `PressAt`, а
снимает `CancelPress`, то есть отпускание, нажатие над панелью редактора и `SetMouseEnabled(false)`.
Каждый тик `ProcessUIInput` передаёт положение мыши в `UpdateScrollbars`. Та переводит точку в
систему полосы, как поле — точку клика, поэтому поворот `local` учитывается, и пишет сдвиг списка.
Длины дорожки и бегунка она берёт у `ThumbPlaceOf`, по которой бегунок и рисуется. Shift читается в
момент нажатия: `InputManager` кладёт его в событие кнопки.

Когда прокручивать нечего, нажатие ничего не двигает, но мышь остаётся за UI. Захват снимается сам,
если полоса или список пропали с экрана или прокручивать стало нечего.

У бегунка три состояния, и каждое рисуется своим материалом:

| состояние | когда | материал |
|---|---|---|
| покой | всё остальное время | `thumb-material` |
| наведение | курсор над самим бегунком, полоса — верхний узел под курсором, и прокручивать есть что | `thumb-hover-material`, без него — `thumb-material` |
| захват | бегунок тянут, в том числе после прыжка с Shift; курсор при этом может уйти с бегунка | `thumb-active-material`, без него — материал наведения |

Состояние считает та же `UpdateScrollbars` каждый тик и хранит его в `UIScrollbarData`. На смену
состояния она меняет материал энтити бегунка через `ChangeMaterial`, а пересоздание энтити ставит
материал текущего состояния сразу. Пока список листается страницами, бегунок в покое или под курсором.
Смена материала пересобирает население сцены ([`WARNINGS.md`](../WARNINGS.md), раздел «UI»).

## Картинка из 9 частей

Рамку списка или панели рисует программа `UINineSlice`. Картинка материала режется на трети по
каждой оси: углы рисуются как есть, а середины сторон и центр повторяются копиями. Поэтому рамка
удлиняется вместе с узлом и не растягивается. Копии идут от верхнего левого угла, обрезается
последняя — у правого и нижнего края, и при росте узла прежние пиксели остаются на месте. Узел
короче двух углов делится пополам, и каждая половина показывает внешнюю часть своего угла.

**Тексель картинки равен пикселю окна.** О размере узла шейдер узнаёт из его матрицы: `Emit`
переводит единичный квад сразу в NDC, поэтому столбец матрицы — сторона узла в долях окна.
Фрагментник читает матрицу своей строки из `DefaultTransformBuffer` и переводит её в пиксели
размером окна из пуша `ui_window_size` — тем же, по которому раскладывает `Emit`. Размер картинки
шейдер берёт из её прямоугольника в атласе, так что с CPU, кроме окна, ничего не приходит.

Отсюда требование к атласу: картинка лежит в атласе **без мипов**. Атлас с мипами при загрузке
ужимает сторону-степень двойки ([`gpu/textures.md`](gpu/textures.md)), и трети разошлись бы с
файлом. Атлас без мипов кладёт картинки вплотную, поэтому выборка не подходит к краю картинки ближе
полутекселя. Уровень мипа шейдер берёт нулевой явно: на стыке копий координата прыгает, и
автоматический выбор уровня дал бы линию по каждому стыку.

Шейдер разложен на три слоя, как поверхность Lit ([`gpu/shaders/hlsl.md`](gpu/shaders/hlsl.md)):

| слой | файл | что даёт |
|---|---|---|
| пролог | `ui/nine_slice_api.hlsl` | сэмплеры, таблица UVL, слоты пушей, `SampleNineSlice` |
| пользовательская часть | `ui/nine_slice_surface.hlsl` у `UINineSlice` | `cbuffer MaterialBlock` и `getColor` |
| основа | `ui/nine_slice.frag.hlsl` | `main`: прозрачность узла, отброс прозрачных пикселей |

Параметры материала `UINineSlice` — одноимённый тип с одним тинтом. Игра пишет свою
пользовательскую часть так же, как свою поверхность Lit, и заводит программу записью `shaders.json`:
вершинник `ui_vs` с его буферами (`DefaultTransformBuffer`, `DefaultPositionIndexBuffer`,
`DefaultInstanceBuffer`, `UIClipRank`, `UIClipIndex`, `UIClipRect` — в этом порядке), проход
`DefaultUIPass`, `DefaultTransformBuffer` во фрагментных буферах, слот `Albedo`. Пуши такая программа получает без кода: метки стоят в прологе и в самом `ui.vert` (камера
UI-прохода, `ui_camera`).

## Клики: реакция на нажатие

Приложение регистрирует функтор на `id` узла вызовом `OnClick`. Реестр относится к UI текущей сцены:
`Reset` при загрузке сцены очищает его, а генераторы сцены заполняют заново, поэтому узлы с одним `id`
в UI разных сцен получают свои функторы. Перезагрузка файла реестр сохраняет: его ключ — имя, и новая
нумерация узлов на него не влияет. Экземпляры цикла делят один `id`, и функтор различает их по ключу
экземпляра, который получает аргументом.

Клик проходит три шага:

| шаг | поток | что происходит |
|---|---|---|
| приём | main | `InputManager` кладёт нажатие и отпускание в очередь с координатами события |
| поиск цели | sim, перед тиком приложения | `EngineContext::ProcessUIClicks` передаёт левую кнопку в `PressAt` и `ReleaseAt`; нажатие и отпускание на одной цели добавляют клик в очередь |
| вызов | sim, в тике приложения | `ExecuteClicks` вызывает функторы очереди |

Цель ищется обходом дерева от корня. Среди показанных узлов под точкой выбирается верхний, то есть с
наименьшим `ndc_z`, среди тех, что рисуются, принимают клик — имеют свой функтор или служат полем
ввода — или прокручиваются. У прокручиваемого бокса в счёт идёт его область без `padding`. Целью становится ближайший к нему принимающий клик узел на пути от корня: сам верхний узел или
его предок. Поэтому клик по тексту внутри кнопки достаётся кнопке, а панель без функтора поверх кнопки
клик забирает, и цели нет.

Очередь хранит `id` и ключ экземпляра, поэтому клик переживает перезагрузку файла. Нажатие над панелью
редактора сбрасывается, и узлы под панелью клика не получают.

## Поле ввода

`<input>` — текстовый лист с одной дополнительной ролью: клик по нему начинает ввод. Содержимое пишется
как у `<text>` и ссылается ровно на одну переменную. Она служит черновиком ввода, а текст вокруг неё
остаётся подписью:

```html
<input id="name_field">Name: {{name_input}}</input>
```

Индекс в ссылке задаёт элемент переменной, поэтому поля внутри `<for>` пишут каждое в свой элемент.
Показ идёт обычной связью текста. Приложение читает черновик через `GetVar`: каждый тик, когда значение
применяется сразу, или в функторе кнопки, когда оно применяется по подтверждению.

**Активное поле одно**, и `UI_Manager` хранит его узел, переменную, ключ элемента и позицию ввода. `PressAt`
ставит фокус, если цель нажатия — поле, и снимает его при любой другой цели. Снимают фокус также Enter, нажатие над
панелью редактора, перезагрузка файла и скрытие узла поля.

Ввод идёт через три шага:

| шаг | поток | что происходит |
|---|---|---|
| включение | sim, затем main | `ProcessUIInput` передаёт наличие фокуса атомарным флагом, `Engine::UpdateTextInput` вызывает `SDL_StartTextInput` и `SDL_StopTextInput` |
| приём | main | `InputManager` кладёт текст, нажатия клавиш с автоповтором и повороты колеса в одну очередь |
| правка | sim, перед тиком приложения | `HandleInput` применяет текст и клавиши к переменной через `GetVar` и `SetVar` |

Очередь одна, потому что результат зависит от порядка букв и Backspace внутри тика. Текст приходит из SDL
с учётом раскладки и Shift, служебные клавиши приходят только как нажатия.

Позиция ввода — индекс символа в значении переменной. Клик ставит её на ближайшую границу символов, текст
вставляется в неё, стрелки, Home и End её двигают, а Backspace и Delete стирают символ рядом с ней. Значение хранится в
UTF-8, и индекс переводится в байты только на время правки, поэтому позиция всегда стоит на границе
символа. Если приложение укоротило значение, следующая правка зажимает позицию в его длину.

### Каретка

Каретка — своя энтити у каждого `<input>`. `EmitNode` создаёт её вместе с энтити поля и делает поле её
родителем: `ParentComponent` и `LocalMatrices` дают ей матрицу поля с его поворотом и масштабом, а удаление
поля удаляет и её. Рисуется она как любая энтити, поэтому её вид задают материал и модель:

| свойство | что задаёт |
|---|---|
| `caret-material` | цвет каретки в `bg_color`, цвет буквы под ней в `text_color`, текстура или своя программа прохода UI |
| `caret-quad` | модель |
| `caret-width` | ширина; `100%` равен высоте строки и даёт квадрат |
| `caret-gap` | сдвиг влево от буквы; буква при этом стоит на месте |

Высота каретки равна высоте строки. Каретку ведёт `UpdateCaret`: он идёт в подготовке кадра сразу после
`Emit` и каждый кадр заново выставляет каретке активного поля место, текст и фазу мигания.

**Место.** `WrapText` записывает для каждого символа строку, x и номер записи в потоке глифов, плюс одну
запись за последним символом. Пробелы, не вошедшие в строку, ширины ей не добавляют, но записи получают,
поэтому каретка проходит и через них. Номер записи — длина подписи перед переменной плюс позиция ввода:
у каждого символа текста своя запись. Матрица поля уже содержит его размер, поэтому `LocalMatrices` задаёт
положение и размер каретки в долях поля.

**Буква.** Каретка получает хвост потока глифов от своего места и отступ текста `indent_lines`. `caret-gap`
сдвигает квад влево, а отступ возвращает текст вправо на ту же величину, поэтому буква остаётся на своём
месте. Шейдер рисует только то, что влезло в квад, а на переносе останавливается. Поэтому каретка не шире
сдвига стоит перед буквой, чуть шире перекрашивает её край, а ещё шире — букву целиком и соседние. Буква
совпадает с буквой поля, потому что глиф рисуется внутри своей ширины. Каретка непрозрачна и
лежит впереди всех узлов, поэтому порядок рисования на неё не влияет.

Сдвиг и ширина лежат в стиле поля и переводятся в пиксели по его шрифту, а шейдер получает отступ в высотах
строки пятым числом записи `TextIndex`. Материал описывает только вид, поэтому один материал служит полям с
любым шрифтом и любым сдвигом.

**Клик.** `PressAt` идёт по тем же записям в обратную сторону. Точка окна переводится в систему поля, поэтому
поворот поля учтён. Высота строки даёт строку, а середина буквы разделяет две соседние позиции. Клик правее
конца строки ставит позицию в её конец, ниже текста — на последнюю строку, по подписи — на край значения.

**Мигание.** Цикл длится 1,2 с, из них 0,8 с каретка видна. Фокус и каждая правка начинают цикл заново.
Мигание пишет `Renderable.alpha`: шейдер умножает на него и фон, и текст, а при нуле отбрасывает пиксель.
`HideEntity` вызывается только при смене фокуса, потому что он пересчитывает список отрисовки по всей сцене.

### Текстовый режим

Текстовый режим SDL — один булев флаг окна на оба интерфейса. Бэкенд ImGui сам выключает его из кадра на
рендер-потоке, когда поле редактора теряет фокус, поэтому main сверяет состояние в каждом проходе цикла.
Выключение пропускается, пока текст нужен панели редактора. Вызовы идут только при смене состояния: они
сбрасывают недонабранную мёртвую клавишу.

## Захват мыши и клавиатуры

Интерфейс и приложение делят мышь и клавиатуру. Приложение спрашивает, занято ли устройство, и само
выбирает, какие его действия подчиняются ответу.

`EngineContext::WantCaptureMouse` отвечает, занята ли мышь панелью редактора или UI сцены.
`UI_Manager::WantCaptureMouse` занят, пока курсор над узлом, перекрывающим клик, пока держится нажатие,
начатое над таким узлом, и пока поле ввода в фокусе. Удержание нажатия сохраняет захват, когда курсор с
зажатой кнопкой уходит с узла. Прокручиваемый бокс перекрывает клик всей видимой областью, даже без
материала, поэтому колесо над промежутком между строками списка достаётся списку, а не камере.

`EngineContext::WantCaptureKeyboard` отвечает, занята ли клавиатура полем ввода UI или активным элементом
редактора. Навигация клавишами по панелям редактора клавиатуру не занимает (`ConfigNavCaptureKeyboard`),
поэтому после клика по панели клавиши остаются у приложения.

`UI_Manager::SetMouseEnabled` выключает мышь для UI на время действия приложения. Выключенный UI не
принимает нажатия, не захватывает мышь и сбрасывает незавершённое нажатие. Приложение держит признак своего
действия само: действие начинается вне UI и длится до отпускания кнопки, даже если курсор проходит над
узлами.

## Правки редактора и сохранение

Инспектор правит стиль и материал узла командами, и sim-поток записывает правку не только в узел, но
и в элемент файла, из которого узел построен, — **перекрытием**: литеральным значением одного
свойства, например `width: 300px`. Перекрытия применяются после всех объявлений элемента, поэтому
стиль, пересобранный по `SetVar`, правку сохраняет. Значение, возвращённое к тому, что даёт файл,
перекрытие снимает.

Правится не всё. Свойство, значение которого решает объявление с `{{…}}`, в инспекторе неактивно:
литерал поверх оборвал бы связь с переменной. Экземпляры `<for>` не правятся вовсе: у всех
экземпляров один элемент, и правку одного экземпляра файл не выражает. Сдвиг гизмо, кнопки Z и
матрица `local` живут только в узле: свойств для них в формате нет.

Кнопка Save в разделе UI иерархии активна, пока есть несохранённое. `UI_Manager` держит два текста:
рабочую копию, из которой построено дерево, и снимок файла на диске с последней загрузки или записи.
Save идёт командой на sim-поток под `scene_swap_mutex`: сверяет файл на диске со снимком, вписывает
перекрытия в рабочую копию, строит из неё дерево заново и пишет её на диск через временный файл.
Файл, который успели поправить в другом редакторе, Save не перезаписывает, а оставляет в логе
просьбу о Load. Текст, который не загрузился, на диск не попадает. Load, наоборот, берёт файл с
диска и несохранённые правки отбрасывает. Оба строят дерево заново, и выделенный UI-узел
сбрасывается.

Перекрытие вписывается точечно. Разбор помнит место каждого значения в файле — смещение от начала и
длину, — и запись меняет только эти байты: комментарии, отступы и правила остаются как были.

| где решается значение свойства | что делает Save |
|---|---|
| литерал того же свойства в атрибуте `style` | заменяет значение на месте |
| правило `<style>`, сокращение (`padding` при правке `padding-left`) или умолчание | дописывает объявление в конец атрибута `style`, а если атрибута нет — вставляет его в тег |

Атрибут `style` — последняя ступень каскада, поэтому дописанное объявление перекрывает любые
правила, и правила `<style>` Save не меняет. Значения пишутся каноническими именами (`flex-start`,
а не `start`) и кратчайшей записью чисел. Режима размера Grow в формате нет: такой размер
записывается как `width: auto` и `flex-grow`, и после перезагрузки инспектор показывает Auto и Grow.

## Инварианты и грабли

- **При ошибке в файле дерево остаётся прежним.** Загрузка проверяет документ целиком до первого
  узла.
- **`flex-direction` по умолчанию — `column`**, как в Yoga. В браузере по умолчанию `row`, и
  разметка, перенесённая оттуда без явного направления, ляжет иначе.
- **`flex-shrink` по умолчанию — 0**, как в Yoga. В браузере по умолчанию 1: ребёнок, которому
  не хватило места в родителе, там сжимается, а здесь вылезает за родителя, пока ему не задан
  `flex-shrink`.
- **Стили не наследуются.** Шрифт и другие общие свойства задаются правилом `*` или правилом тега.
- **Порядок имён в `class` на результат не влияет.** При равной специфичности побеждает правило,
  которое ниже в файле.
- **`{{` всегда открывает подстановку** — в тексте и в значениях свойств.
- **Подстановка проверяется при загрузке.** `width: {{w}}px` у переменной без `default` не
  загрузится: пустая подстановка даёт `px`, а это не длина.
- **Связь из правила `<style>` получает каждый подошедший элемент.**
- **Правка редактора живёт в элементе файла, а не в узле.** Пересборка стиля по `SetVar` её не
  стирает, а Load отбрасывает несохранённую.
- **Save пишет только в атрибут `style` элемента.** Свойство из правила класса после Save
  перекрыто у одного элемента, а правило остаётся прежним и действует на остальные.
- **Файл, изменённый снаружи после загрузки, Save не перезапишет.** Нужен Load, и правки редактора
  при этом теряются.
- **Сдвиг гизмо, Z и `local` в файл не сохраняются.** Save строит дерево заново и сбрасывает их.
- **Энтить есть у каждого узла, а `Renderable` — только у рисующего.** Энтить из `GetNodeEntity`
  может не иметь отрисовки: код, читающий её `Renderable` напрямую, сначала проверяет `Has`.
- **UI-энтити пересоздаются только на структурном изменении дерева.** Состояние, записанное на
  энтить узла (вариант текстуры), пересоздание сбрасывает. Скрытие его не трогает.
- **Видимость энтити узла задаёт `Emit` по `display` и запасу.** `visible`, выставленный энтити узла
  в обход стиля, `Emit` перепишет на следующей раскладке.
- **Номер узла действует до перезагрузки файла.** Load и Save нумеруют узлы заново, поэтому код
  хранит `id` и находит узел через `FindNode`. Рост цикла дописывает узлы в конец, и прежние номера
  не меняются.
- **Функторы клика живут до следующей загрузки сцены.** Их регистрирует генератор сцены: он идёт
  после `Reset` и загрузки файла, а регистрация до `LoadScene` снимается этим `Reset`.
- **Рисуемый узел перекрывает клик, даже если функтора у него нет.** Узел только для раскладки клик
  пропускает.
- **Клик по узлу приложение видит и как обычное нажатие кнопки мыши.** Захват — это ответ
  `WantCaptureMouse`, и проверяет его само приложение.
- **Enter, завершивший ввод, приложение видит как обычное нажатие.** Фокус снимается перед тиком
  приложения, и в этом тике клавиатура уже свободна.
- **Символ вне атласа остаётся в переменной и показывается глифом `.notdef`.** Этот глиф шрифт отводит под
  отсутствующие символы: в одних шрифтах это рамка, в других пустое место с шириной. В списке глифов у
  каждого символа текста поэтому своя запись.
- **Пустое поле занимает столько, сколько задаёт стиль.** Ширина текста при пустом значении нулевая, и
  без `width` или растяжения родителем кликнуть по полю негде. Каретка такого поля тоже не видна: нулевая
  ширина входит в матрицу родителя.
- **Каретка рисуется поверх рамки поля.** Шейдер обрезает только текст поля, поэтому `UpdateCaret` прижимает
  каретку к правому краю, когда текст шире поля. Ниже края поля она выходит, если строки в него не влезли, а
  перед первой буквой `caret-gap` выводит её за левый край.
- **Сдвиг `caret-gap` залит цветом каретки.** Широкая каретка закрывает на эту величину край предыдущей
  буквы.
- **Каретка лежит впереди всех узлов**, и элемент, перекрывший активное поле, её не закроет.
- **Полупрозрачные пиксели каретки зависят от порядка рисования.** Проход UI пишет глубину, а группы внутри
  него идут в порядке появления рецептов. Каретка, нарисованная раньше поля, закроет его своей глубиной и
  в полупрозрачных пикселях покажет то, что лежит за полем.
- **`caret-material` и `caret-quad` читаются один раз при загрузке**, как `quad`. `caret-width` и
  `caret-gap` — часть стиля и принимают `{{ }}`.
- **`SetMouseEnabled` действует на нажатия и захват.** `NodeContains` считает только геометрию, поэтому
  наведение, построенное на нём, продолжает работать при выключенной мыши.
- **Индекс в `[…]` — индекс цикла или число.** Переменная в индексе — ошибка загрузки: связь
  экземпляра заводится на один элемент при постройке и потом его не меняет.
- **Новый экземпляр появляется в подготовке кадра.** `SetVar` числа только помечает связь, поэтому
  `FindNode` того же тика нового экземпляра ещё не найдёт.
- **Рост цикла сверх запаса пересоздаёт все энтити UI.** Это структурное изменение дерева, как
  добавление узла; переключение в пределах запаса энтити не трогает.
- **Индекс цикла не совпадает с именем `<var>` и внешнего индекса.** Иначе одно имя значило бы
  две вещи, и загрузка это запрещает.
- **Текстовый узел — лист.** У узла с measure-функцией Yoga запрещает детей: вставка ребёнка в текст
  падает на её assert.
- **Отступ текста задаёт родительский бокс.** Шейдер рисует текст от угла рамки узла, поэтому
  `padding` текстового узла всегда 0.
- **Текст за рамкой своего узла не рисуется** — его рисует quad узла. За родительский бокс без
  `overflow` он вылезти может: у текстового узла своя рамка, и без `flex-shrink` Yoga не сжимает её
  под родителя.
- **Оси `overflow` независимы.** В CSS `visible` рядом с другим значением на второй оси становится
  `auto`, а здесь ось с `visible` не режется.
- **`overflow` режет внутри `padding`.** В CSS край обрезки — внешний край отступа, и содержимое
  видно в `padding`. Здесь отступ остаётся под рамку картинки бокса, и потомок в него не заходит.
- **Обрезка не учитывает `local`.** Бокс, повёрнутый или увеличенный гизмо, режет потомков по своей
  рамке из раскладки.
- **Появление и снятие `overflow` у бокса пересоздаёт энтити UI.** Состояние на энтити, например
  вариант текстуры, при этом сбрасывается. Позицию прокрутки пересоздание не трогает.
- **Предел прокрутки считается по прямым детям.** Внук, вылезший за своего родителя, и масштаб
  `local` в длину содержимого не входят.
- **Колесо выбирает список по пределу, а не по остатку хода.** Вложенный список, докрученный до
  края, держит колесо, и внешний под ним не прокрутится, пока курсор над вложенным.
- **`hidden` колесом не прокручивается**, хотя раскладка у него такая же, как у `scroll`.
- **Прокручиваемый бокс перекрывает клик и без материала.** Узел только для раскладки клик
  пропускает, а пустой список с `overflow: scroll` его забирает.
- **Колесо над UI приложение видит и как обычный поворот.** Как и с кликом, занятость мыши
  проверяет само приложение через `WantCaptureMouse`.
- **Полоса в колонке встаёт под списком.** Вертикальной полосе нужен родитель с
  `flex-direction: row`, горизонтальной в колонке — `width`: без него она растянется на ширину
  родителя.
- **Полоса не прячется, когда прокручивать нечего.** Бегунок встаёт во всю длину полосы, а место в
  раскладке остаётся за полосой.
- **Нажатие на полосу не кликает её предка.** Полоса внутри бокса с функтором забирает нажатие, и
  функтор по ней не вызывается.
- **`overflow` списка проверяется при загрузке.** Полоса списка, у которого переменная потом снимет
  прокрутку по её оси, остаётся с бегунком во всю длину.
- **Свойства бегунка читаются один раз при загрузке**, как `caret-material`. Материал
  дорожки — обычный `material` и принимает `{{ }}`.
- **Толщину полосы `auto` не задаёт.** `width: auto` у вертикальной полосы — те же 14 пикселей;
  растянуть её поперёк можно через `flex-grow` или `N%`.
- **Переносы `Emit` делает с запасом в пиксель.** Yoga округляет раскладку, и итоговая ширина
  расходится с замеренной на долю пикселя; без запаса строка, влезшая при замере, перенеслась бы, и
  текст стал бы выше своего узла.
- **Масштаб через `local` не растягивает картинку из 9 частей.** Размер узла шейдер берёт из матрицы,
  куда `local` уже вошёл: увеличенный узел получает больше копий, а углы остаются прежнего размера.
- **`UINineSlice` не переключает варианты текстуры.** В прологе нет раскладки вариантов, и рисуется
  дефолт слота.
- **Программа с `ui_vs` живёт только в UI-проходе.** Пуш `ui_camera` читает параметры прохода как
  `UICameraPushData`.
- **Программе с `ui_vs` нужны все шесть его буферов.** Без буферов обрезки в `vs_buffers` вершиннику
  нечем читать рамки.
