# Каллинг: пер-проходные регионы индиректа и out_pib

Статус: РЕАЛИЗОВАНО (ветка komp, 2026-09-01). Промежуточные формы — «группы камер» (прогоны
проходов + инжект в BatchBuilder) и расчёт регионов в DefaultRenderPassSet — удалены целиком.

## Проблема (исходная)

Индирект и out_pib были декартовым произведением камер на содержимое всех проходов:
`(1+L) * TC` команд и `(1+L) * N` записей PIB. Камера рисует только свои проходы, поэтому
в блоке теневой камеры лежали main-команды и наоборот, и всё это чистилось и переливалось
каждый кадр.

## Раскладка

Регион НА ПРОХОД (порядок = ordinal), внутри — блок на каждый ДРОУ прохода за кадр
(`PassRegion::command_blocks_count`), в блоке только его команды/записи:

    индирект: [ shadow: L x 10 ][ main: 1 x 12 ][ transparent: 1 x 2 ][ debug: 1 x 0 ][ UI: 1 x 2 ]
    out_pib:  [ shadow: L x 22 ][ main: 1 x 23 ][ transparent: 1 x 5 ][ debug: 1 x 0 ][ UI: 1 x 2 ]

Размер = сумма по проходам `blocks*commands` (при L=4 это 56 команд против 130 у старого
произведения; out_pib 118 int против 260). Пустой проход даёт нулевой вклад — префиксная
сумма переступает через него, база у него совпадает с базой следующего, и это безвредно:
нулевой регион никто не разыменовывает.

В `first_instance` каждой команды лежит АБСОЛЮТНЫЙ адрес её куска в out_pib:

    fi = pib_base(прохода) + номер_блока * pib(прохода) + локальное_смещение

`SV_InstanceID = first_instance + i` (Vulkan; в D3D12 иначе — движок просит только SPIRV),
поэтому все вершинники читают просто `OutPib[instanceID]`, без арифметики блоков.

## Кто что делает

**Фаза слепков в `Engine::PrepareFunc`** — порядок явный, а не выведенный из порядка
регистрации инструкций:

    batch_builder->StampLayoutSnapshot(slot)                 // что рисуем
    light_data_module->StampShadowCameras(..., slot)         // чем смотрим
    pass_manager->StampRegions(slot, bb->AskLayout(slot))    // как это разложено
    ...ExecuteUpdateInstructions                             // size-функции только читают

- **`PassManager`** — владелец проходов и порядка, поэтому и владелец раскладки.
  `StampRegions` штампует регионы слота (единственная префиксная сумма в движке),
  `AskRegions(slot)` отдаёт штамп всем. Проход заявляет своё число блоков инструкцией
  `CreateRegionCountInstruction(pass_name, fn)`, зарегистрированной рядом с его созданием.
  **Инструкция может вернуть только ЧИСЛО** — границы назвать нечем, поэтому покрытие
  остаётся непересекающимся при любом её ответе. Нет инструкции = один блок.
- **`RenderPassStandardBody(cb, rp, bm, region_index, push)`** — тело передаёт номер своего
  блока (обычный проход — 0), байты считает менеджер по штампу. Наружу байты не отдаются,
  чтобы не появился второй способ их посчитать. Если `region_index` вышел за заявленное
  число блоков — лог с именем прохода и обоими числами, но дроу выполняется: иначе
  рассинхрон выглядел бы как «проход просто не рисуется».
- **`BatchBuilder`** — нумерует команды ЛОКАЛЬНО для прохода (счётчик свой на проход).
  Никакого внешнего знания: выводится из собственного дерева.
- **`PIB_DataModule::StoreEntityToCmd`** — та же пер-проходная нумерация.
- **`IndirectDataModule`** — исполнитель чужой раскладки: пишет регионы пасс-мажорно с
  ребейзом `first_instance`, гейт `{BatchesRevision, штамп регионов}` per slot (покадрово
  меняется только `num_instances`, его обнуляет `culling_clear` на GPU).
- **`DefaultShaderSet` (game и mygame)** — culling-программа НА ПРОХОД с батчами, все пять
  создаются локальным `CreateCullingProgram(ctx, sm, pm, имя, проход, камерный_буфер)`:
  различаются только имя и камерный буфер, числа региона берутся из штампа по ординалу.
  `SetCullingPibPrograms(ctx)` о свете не знает вовсе.
- **Шейдеры**: `culling_pib.comp` — CullParams {range_start, range_count, num_blocks,
  cmd_base, commands}, слот команды = `cmd_base + b*commands + k`; адрес out_pib берётся из
  самой команды. `culling_clear` обнуляет `total_commands` слотов.

## Новый проход — целиком в своём файле

1. `CreateRenderPass(MY_PASS, body, rptd, pass_index)` — вставка между другими работает,
   ординалы и базы пересчитает штамп;
2. если у прохода свои камеры — `CreateRegionCountInstruction(MY_PASS, [src](slot){...})`
   рядом, плюс свой камерный буфер с апдейт-инструкцией;
3. sp прохода;
4. `CreateCullingProgram(..., MY_PASS, MY_CAMERA_BUFFER)`;
5. в теле — цикл по своим блокам с `RenderPassStandardBody(..., region_index, ...)`.

Ни DRPS, ни ядро не открываются. Проход без своих камер не объявляет ничего.

## Инварианты и грабли

- **Инструкция счёта регионов обязана читать слепки слота (`Ask*`), а не живое состояние**, и
  её число обязано совпадать с числом дроу в теле прохода. Расхождение теперь ловится логом в
  `RenderPassStandardBody`, а не проявляется чужой геометрией.
- **Вся адресная арифметика — сложения и умножения, ни одного вычитания.** Беззнаковое
  вычитание молчит и в шейдере, и на CPU.
- **`culling_clear` обязан быть shader_batch[0] в CULLING_PASS** (`WARNINGS.md`) — он
  создаётся первым в `SetCullingPibPrograms`.
- **Порядок проходов для каллинга не значим**, порядок регистрации инструкций — тоже
  (слепки пишет своя фаза). Единственный оставшийся порядковый инвариант — внутри
  `SetCullingPibPrograms`.
- **Клэмп теневого цикла по слоям атласа (8) — только для отрисовки**, число блоков считается
  по полному числу камер.
- **Команда с нулём инстансов носит бессмысленный `first_instance`** — нормально, GPU не
  заведёт ни одного инстанса. Не валидировать.
- **UI не отсекается вовсе**: `BoundSphereDataModule` пишет архетипам с `UIComponent`
  вырожденную сферу `w<0` (NDC-трансформ мировым фрустумом мис-каллился бы), и скаттер
  пропускает их безусловно — тот же канал, что у transformless и моделей без POSITION.
  Камерный буфер у `csp_cull_ui` из-за этого фактически не читается.
- Цена пер-проходности: диспатч на проход (мелкие проходы дают микро-диспатчи, пустые —
  нулевые и пропускаются) — осознанный размен на независимость проходов.

## Проверка

Сделано: смоук на сцене с 4 теневыми камерами — 60 FPS, ноль ошибок; индирект 1120 Б,
out_pib ~472 Б; гейт индиректа: `.store` n=3 в первом окне, n=0 дальше. Обе игры собираются.

Осталось: глазами (тени на месте, объекты не пропадают и не дублируются); сцена без теневого
света (L=0); добавление/снятие теневого света на живой сцене (бьёт по гейту); 1М кубов.
