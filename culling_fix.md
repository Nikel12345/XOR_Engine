# Каллинг: пер-проходные регионы индиректа и out_pib

Статус: РЕАЛИЗОВАНО (ветка komp), финальная форма — ПЕР-ПРОХОДНАЯ (2026-09-01).
Промежуточная форма с «группами камер» (прогоны проходов, GroupSpan, инжект в BatchBuilder)
удалена целиком: группа была оптимизацией слияния culling-диспатчей и не окупала свою механику.

## Проблема (исходная)

Индирект и out_pib были декартовым произведением камер на содержимое всех проходов:
`(1+L) * TC` команд и `(1+L) * N` записей PIB. Камера рисует только свои проходы, поэтому
в блоке теневой камеры лежали main-команды и наоборот, а всё это чистилось и переливалось
каждый кадр.

## Итоговая раскладка

Регион НА ПРОХОД (порядок = ordinal), внутри региона — блок на каждый ДРОУ прохода за
кадр (Region::command_blocks_count; обычно = числу его камер, у безкамерного UI — один),
в блоке только его команды/записи:

    индирект: [ main: 1x12 ][ transparent: 1x2 ][ UI: 1x2 ][ shadow: L x 10 ] ...
    out_pib:  [ main: 1x23 ][ transparent: 1x5 ][ UI: 1x2 ][ shadow: L x 22 ] ...

Размер = сумма по проходам blocks*commands (56 команд / 118 int на смоук-сцене с L=4 против
130 / 260 у старого произведения). Итоги совпадают с групповой формой — меняется только
нарезка.

В `first_instance` каждой команды лежит АБСОЛЮТНЫЙ адрес её куска в out_pib:

    fi = pib_base(прохода) + номер_блока * pib(прохода) + локальное_смещение

`SV_InstanceID = first_instance + i` (Vulkan; в D3D12 иначе — движок просит только SPIRV),
поэтому все вершинники читают просто `OutPib[instanceID]`.

## Кто что делает

- `RenderSnap::Region/Regions` (`RenderSnapshot.h`) — только словарь типов, общий для
  вычислителя и потребителей. Контракт: базы предполагают пасс-мажорную запись буфера.
- `DefaultRenderPassNamespace::AskRegions(pm, bb, ldm, slot)` (`DefaultRenderPassSet.cpp`) —
  ЕДИНСТВЕННЫЙ вычислитель регионов (префиксная сумма по слепку) и ЕДИНСТВЕННОЕ место со
  знанием о камерах: теневой проход рисуют L световых камер, любой другой — одна камера
  игрока. Новый тип камер = ещё одна ветка здесь + своя culling-программа. Отдельного
  BuildRegions больше нет: у него был один вызывающий, а параметр cams_per_pass существовал
  только ради границы между ними.
- `BatchBuilder::FinalizeOffsets` — индекс команды в слепке ЛОКАЛЬНЫЙ для прохода (счётчик
  свой на проход). Никакого внешнего знания: выводится из самого дерева.
- `PIB_DataModule::StoreEntityToCmd` — та же пер-проходная нумерация, тоже без внешнего
  знания.
- `IndirectDataModule` — пишет регионы пасс-мажорно с ребейзом first_instance; гейт
  `{BatchesRevision, число теневых камер}` per slot (покадрово меняется только
  num_instances, его обнуляет culling_clear на GPU). Гейт безопасен при ресайзе: размер —
  функция тех же двух чисел.
- Culling-программы (`DefaultShaderSet.cpp`, game и mygame) — ПО ОДНОЙ НА ПРОХОД с батчами:
  csp_cull_shadow (LIGHT_CAMERA_BUFFER) + csp_cull_main/transparent/debug/ui (CAMERA_BUFFER).
  Каждая пушит регион своего прохода (ordinal захвачен на регистрации — MainInit идёт после
  FillRenderPasses). Копипаст намеренный, возможный следующий шаг — фабрика по таблице.
  `csp_culling_clear` ОБЯЗАН создаваться первым (shader_batch[0], WARNINGS.md);
  total_slots = сумма по проходам.
- Дроу: ВСЕ проходы зовут `PassIndirectOffset(pm, bb, ldm, rp, camera_index = 0)` =
  `(cmd_base + camera_index * commands) * 20` по rp.ordinal; у одиночных проходов камера 0,
  теневой зовёт по разу на световую камеру.
- Шейдеры: `culling_pib.comp` — CullParams {range_start, range_count, num_blocks, cmd_base,
  commands}, слот команды = cmd_base + b*commands + k; адрес out_pib берётся из самой
  команды. Вершинники — `OutPib[instanceID]`.

## Инварианты и грабли

- **Вся адресная арифметика — сложения и умножения, ни одного вычитания.** Беззнаковое
  вычитание молчит и в шейдере, и на CPU, а промах даёт запись в чужой регион.
- **Порядок проходов больше НЕ значим для каллинга** — пер-проходным регионам всё равно.
  Инвариант «теневой проход первый» умер вместе с группами.
- **Новый проход с батчами обязан получить culling-программу**, иначе его num_instances
  останутся нулями и он просто не нарисуется (регион у него есть — дефолт 1 камера).
  Проход с СОБСТВЕННЫМИ камерами — ещё и строку в AskRegions.
- **L для адресов — неклэмпнутый** (клэмп по 8 слоям теневого атласа — только для цикла
  отрисовки).
- **Команда с нулём инстансов носит бессмысленный first_instance** — это нормально, GPU не
  заведёт ни одного инстанса. Не валидировать.
- Debug культится против камеры игрока (мировые коллайдеры — тест осмыслен). UI — НЕТ:
  BoundSphereDataModule пишет архетипам с UIComponent вырожденную сферу w<0, и скаттер
  пропускает их безусловно (NDC-трансформ мировым фрустумом мис-каллился бы). Это тот же
  канал «w<0 = видим всегда», что у transformless и моделей без читаемого POSITION.
  Камерный буфер у csp_cull_ui из-за этого фактически не читается — программа оставлена
  единообразной с остальными.
- Цена пер-проходности: диспатч на проход (на смоук-сцене 4 вместо 2; большие диспатчи не
  делятся) и «пустые» микро-диспатчи у мелких проходов — осознанный размен на простоту.

## Проверка

1. Смоук (4 теневые камеры, Debug): 60 FPS, 0 ошибок; индирект 1120 Б, out_pib ~472 Б;
   гейт индиректа: .store n=3 на первом окне, n=0 дальше.
2. Осталось глазами: тени, отсутствие пропаж/дублей объектов; сцена с L=0; добавление/
   снятие теневого света на живой сцене (бьёт по гейту {ревизия, L}); 1М кубов.
